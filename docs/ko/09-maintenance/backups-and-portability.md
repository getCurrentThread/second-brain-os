# 백업과 이식성

<a id="sync-is-not-backup"></a>

## 동기화는 백업이 아니다

이것이 이 페이지의 전부이며, 거의 모든 사람이 저지르는 실수입니다.

동기화는 전파합니다. 자동화가 페이지 이백 개를 엉망으로 다시 써도, 동기화는 그 피해를 몇 초 안에 모든 기기에 충실히 복사합니다. 파일이 삭제되면 모든 곳에서 삭제됩니다.

백업이란 원본의 변경을 따라가지 않는 사본을 뜻합니다. 적어도 하나는 동기화 경로에서 분리되어 있어야 합니다.

<a id="a-workable-arrangement"></a>

## 쓸 만한 구성

**Git 원격 저장소,** 비공개로 두고 실행할 때마다 푸시합니다. 버전이 관리되므로 파일 백업이 해 주지 못하는 "3주 전에는 어떤 모습이었나"까지 다룹니다.

**동기화**는 여러 기기에서 작업하기 위한 것으로, 이미 쓰는 어떤 종류든 상관없습니다.

**정기 아카이브**를 외부 저장소나 별도 클라우드 저장소에 둡니다. 위의 둘 어느 쪽과도 연결하지 않습니다. 한 달에 한 번이면 충분합니다.

사본을 세 개 두고 그중 하나를 단순하고 느리게 두는 구성이, 실제로 일어나는 실패 모드를 견뎌 냅니다.

<a id="test-a-restore"></a>

## 복원 시험하기

한 번이면 됩니다. 아카이브를 가져다 다른 곳에 복원하고, Obsidian에서 열어 링크가 동작하는지 확인하십시오.

시험하지 않은 백업은 꼭 가장 나쁜 순간에 실패합니다. 흔한 실패는 손상이 아닙니다. 아카이브에 폴더 하나가 빠져 있었거나, 볼트를 동기화 도중에 떠서 쓰다 만 상태로 담았다는 것을 그때 알게 되는 것입니다.

<a id="what-you-are-protecting-against"></a>

## 무엇으로부터 지키는가

디스크 고장이 아닙니다. 드물고, 동기화가 처리해 줍니다.

진짜 위험은 3주 전에 자동화가 조용히 무언가를 잘못했는데 이제야 알아채는 경우입니다. 이때는 이력이 필요하고, 그래서 여기서는 파일 백업보다 Git이 더 많은 몫을 집니다.

<a id="portability"></a>

## 이식성

볼트는 마크다운과 위키링크이므로, 어떤 특정 도구를 떠나도 구조적으로 드는 비용이 없습니다. 가끔 확인할 만한 것은 이렇습니다.

**중요한 것은 파일 밖에 있지 않습니다.** 플러그인 전용 메타데이터, 캔버스 파일, 데이터베이스 내보내기. 모두 부가 기능으로는 괜찮지만, 다른 곳에는 없는 지식을 담아서는 안 됩니다.

**Obsidian 없이도 링크가 풀립니다.** `scripts/link_check.py`가 이를 검증하는데, 위키링크를 스스로 파싱하기 때문입니다.

**에이전트 지시는 볼트 안에 있습니다.** 채팅 기록이나 앱 설정이 아니라 볼트 안입니다. `CLAUDE.md`, 스킬, 커맨드는 폴더와 함께 이동합니다.
