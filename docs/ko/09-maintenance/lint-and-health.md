# 볼트 린트

구조의 부패는 소리가 없습니다. 오류는 나지 않습니다. 페이지의 삼분의 일에 닿을 수 없는데 아무도 알아채지 못해서, 볼트가 서서히 답을 못하게 될 뿐입니다.

<a id="what-a-lint-checks"></a>

## 린트가 점검하는 것

**깨진 링크.** 두 가지로 나뉩니다. 오타나 이름 변경은 고치고, 진짜 빈틈은 `index.md`의 Gaps에 넣습니다.

**고아 페이지.** 어디에서도 링크되지 않는 페이지입니다. 속할 자리를 찾아 링크하거나 삭제합니다.

**스텁.** 링크가 없고 40단어가 안 되는 페이지로, 대개 실패한 인제스트입니다. `raw/`의 원본에서 다시 인제스트하도록 표시합니다.

**스키마 위반.** 프론트매터 누락, 잘못된 유형, 어휘 밖의 태그.

**거의 중복된 페이지.** 비슷한 제목, 겹치는 별칭, 공유하는 백링크.

**인덱스 어긋남.** `index.md`에서 빠진 페이지, 아무 데도 가리키지 않는 항목.

<a id="report-before-repairing"></a>

## 고치기 전에 보고하기

기계적인 수정은 자동으로 이뤄집니다. 판단이 필요한 것은 제안하고 내 결정을 기다립니다.

이 선이 중요한 이유는, 자기 판단으로 페이지를 병합하는 린터는 작업을 망가뜨리고, 보고만 하는 린터는 아무도 손대지 않는 목록만 만들기 때문입니다. 깨진 링크와 스키마 오류는 기계적입니다. 병합과 삭제는 그렇지 않습니다.

<a id="running-it"></a>

## 실행하기

```
/lint
```

주 1회, 또는 원본 자료를 스무 개 넘게 가져온 뒤에 실행합니다. 인제스트마다 돌리지는 마십시오. 잡아내는 것보다 비용이 더 듭니다.

Git 상태가 깨끗할 때 실행하십시오. 잘못된 수정도 `git checkout` 한 번이면 되돌릴 수 있습니다.

Obsidian 안에서는 [Find orphaned files and broken links](https://github.com/Vinzent03/find-unlinked-files) 플러그인이 같은 두 가지 점검을 시각적으로 해 줍니다.

에이전트를 부르지 않고 빠르게 보려면 다음을 실행합니다.

```bash
python3 scripts/link_check.py ~/brain
```

<a id="reading-the-output"></a>

## 출력 읽기

개별 항목보다 개수가 중요합니다. 일주일 뒤 깨진 링크 세 개는 정상입니다. 마흔 개라면 인제스트 지시에서 무언가가 바뀌어, 만들지도 않는 페이지로 가는 링크를 생성하고 있다는 뜻입니다.

둘 다 볼트와 함께 커지므로, 원래 숫자보다 시간에 따른 비율을 추적하십시오. [지표](../05-graphs/metrics.md)를 보십시오.
