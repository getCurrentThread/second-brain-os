# 검토 주기

린트는 구조를 건전하게 지킵니다. 검토는 내가 루프 안에 머물게 하며, 그저 일어나는 일이 아니라 직접 읽을 무언가를 내놓는 유일한 유지보수 작업입니다.

<a id="weekly-ten-minutes"></a>

## 매주, 10분

에이전트가 준비하고, 내가 읽습니다.

```
/review
```

돌아오는 것은 추가된 것, 링크를 가장 많이 얻은 개념, 기록되었으나 아직 풀리지 않은 모순, 열린 질문, 그리고 다음에 읽거나 쓸 구체적인 세 가지입니다.

클러스터가 주목할 부분입니다. 지난주 링크가 향한 곳이 실제로 내 관심이 있던 곳이며, 그곳은 내가 생각하는 곳과 어김없이 다릅니다.

<a id="monthly-structurally"></a>

## 매달, 구조적으로

한 달에 한 번, 한 주가 아니라 볼트 전체를 봅니다.

- 네 가지 [지표](../05-graphs/metrics.md): 추세를 볼 수 있도록 노트에 덧붙임
- 주제에는 계속 자료가 쌓이는데 90일 동안 손대지 않은 개념 페이지
- `index.md`의 Gaps 목록: 애쓰지 않고 생긴 읽기 목록
- 최근에 쓴 페이지 하나의 로컬 그래프: 링크 품질의 표본 점검

<a id="quarterly-honestly"></a>

## 분기마다, 솔직하게

질문 두 가지입니다.

**내가 생각을 바꾼 것은 무엇인가?** [대체 규칙](../04-structuring/contradictions-and-supersession.md) 덕분에만 답할 수 있으며, 그것만으로도 시스템 전체의 값어치를 합니다.

**쓰지도 않을 것을 무엇을 갖고 있는가?** 아카이브로 옮기십시오. 죽은 자료를 안고 있는 볼트는 영원히 모든 질의를 조금씩 나쁘게 만듭니다.

<a id="what-to-prune"></a>

## 쳐낼 것

더는 관심 없는 주제의 원본 자료: 삭제하지 말고 아카이브하십시오. `raw/`에서는 비용이 들지 않으며, 위키 페이지는 없애도 됩니다.

두 번째 자료를 얻지 못한 개념 페이지: 대개 그 아이디어가 실제로는 내게 중요하지 않았다는 뜻입니다.

링크된 것은 하나도 건드리지 않습니다. 다른 다섯 페이지가 기대는 페이지는 글이 어떻든 다른 페이지를 떠받치는 핵심 페이지입니다.

<a id="keep-the-review-short"></a>

## 검토는 짧게

모든 것을 나열하는 검토는 대충 훑고 나서 무시됩니다. 권고는 열 개가 아니라 세 개로 하십시오. 한 주 동안 보고할 만한 것이 없었다면, 그렇다고 말하는 한 줄이 올바른 출력입니다.
