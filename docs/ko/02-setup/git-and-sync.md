# Git, 동기화, 백업

볼트는 텍스트 파일이 든 폴더이므로 이상적인 git 저장소에 가깝고, git이 있기에 에이전트를 무인으로 돌려도 안전합니다.

버전 관리가 없으면 잘못된 실행은 미스터리로 남습니다. 있으면 에이전트가 한 모든 변경이 읽을 수 있는 diff이고, 명령 하나로 되돌릴 수 있습니다.

```bash
cd ~/brain
git init
git add .
git commit -m "initial vault"
```

<a id="what-to-ignore"></a>

## 무시할 것

```
.obsidian/workspace*
.obsidian/cache
.DS_Store
.trash/
```

`.obsidian/`의 나머지는 커밋해서 플러그인 목록과 설정이 볼트와 함께 이동하게 하십시오. API 키는 절대 커밋하지 마십시오. Local REST API 키는 플러그인 데이터에 들어 있으므로, 첫 푸시 전에 `.obsidian/plugins/`에 무엇이 있는지 확인하십시오.

볼트의 어느 부분이든 비공개라면 원격 저장소도 비공개로 두십시오. 세컨드 브레인은 한 사람에 대해 존재하는 문서 중 정보 밀도가 가장 높은 것 중 하나입니다.

<a id="commit-around-agent-runs"></a>

## 에이전트 실행 전후에 커밋하기

큰 인제스트 전과 후에 커밋하십시오. 그러면 잘못된 배치는 오후 한나절의 수작업 복구가 아니라 `git checkout .` 한 줄로 끝납니다. 예약 작업은 실행을 알아볼 수 있는 메시지를 달아 자기 작업을 직접 커밋해야 하며, 그래야 몇 달 뒤에도 이력을 읽을 수 있습니다.

<a id="sync-across-machines"></a>

## 기기 간 동기화

- **Git 원격 저장소:** 무료이고, 버전 관리가 되며, 어디서든 작동합니다. 풀과 푸시를 습관으로 해야 합니다.
- **Obsidian Sync:** 유료이고, 엔드투엔드 암호화되며, 모바일을 제대로 지원합니다.
- **일반 클라우드 드라이브:** 쓸 수는 있지만 단서가 있습니다. 에이전트가 파일을 쓰는 동안 동기화 클라이언트가 파일을 덮어쓰면 충돌 사본이 생깁니다. 이 길을 택한다면 오래 걸리는 에이전트 작업은 한 기기에서만 하십시오.

<a id="backups"></a>

## 백업

동기화는 백업이 아닙니다. 동기화는 잘못된 삭제를 모든 기기에 퍼뜨립니다.

동기화 경로와 연결되지 않은 사본을 하나 두십시오. 외부 저장소로 주기적으로 보관하거나 별도의 원격 저장소를 씁니다. 필요해지기 전에 복원을 한 번 테스트해 보십시오. 막으려는 실패 모드는 디스크가 죽는 일이 아니라, 3주 전에 조용히 페이지 200개를 다시 써 버린 자동화입니다.
