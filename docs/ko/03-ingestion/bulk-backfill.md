# 수년 치 자료 백필

언젠가는 모든 것을 들여오고 싶어질 것입니다. 북마크 폴더, 다운로드 디렉터리, 3년 치 채팅 기록, 읽지 않은 항목이 800개 쌓인 나중에 읽기 대기열까지.

가장 탈이 나기 쉬운 작업입니다. 비용이 많이 들고 몇 시간이 걸리며, 순서를 잘못 잡으면 구조가 아니라 더미처럼 읽히는 위키가 나옵니다. 하지만 단번에 볼트를 정말 쓸모 있게 만들어 주는 작업이기도 하니, 신중하게 해 볼 만합니다.

<a id="order-matters"></a>

## 순서가 중요한 이유

가장 오래된 것부터 처리합니다.

이유는 나중 자료가 앞선 자료가 만든 페이지를 갱신해야 하기 때문입니다. 이렇게 하면 위키에 이해가 발전해 온 과정이 남습니다. 주제에 관한 초기 페이지, 이어지는 정정, 현재의 입장이 차례로 남습니다.

최신 것부터 처리하면 오래된 자료는 들어올 때마다 이미 최종 답이 적힌 페이지와 충돌하고, 그 모순을 일일이 맞춰 줘야 합니다. 에이전트는 모순을 조정하는 데 힘을 다 쓰고, 이력은 거꾸로 나오며, 이 구조가 검색 인덱스보다 나은 단 하나의 장점을 잃게 됩니다.

<a id="batch-always"></a>

## 항상 배치 단위로

배치당 자료 열 개씩 처리합니다. 배치가 끝날 때마다 `index.md`를 갱신하고, `log.md`에 추가하고, 커밋하고, 보고합니다.

```
/backfill raw/archive/2024
```

[`commands/`](../../../commands/README.md)의 `backfill` 명령이 이렇게 동작하며, 배치 사이마다 멈춰서 진행 승인을 기다립니다.

배치로 나누는 이유는 세 가지입니다. 아직 멈출 수 있을 때 비용이 눈에 보입니다. 품질을 계속 확인할 수 있어서, 잘못된 페이지 규약을 400번째 페이지가 아니라 10번째 페이지에서 잡아냅니다. 그리고 작업이 중단되어도 전체가 아니라 배치 하나만 잃습니다.

<a id="check-the-first-batch-properly"></a>

## 첫 배치는 제대로 확인하기

첫 배치가 만든 페이지를 전부 읽습니다. 하나도 빼놓지 않습니다.

모든 페이지에 반복되는 문제를 잡아낼 때가 바로 지금입니다. 설명이 아니라 요약에 그친 페이지, 지나치게 잘게 쪼개진 개념, 장식에 불과한 링크, 잘못된 프론트매터. 계속하기 전에 `CLAUDE.md`를 고치고 그 배치를 다시 실행합니다.

첫 배치에서 놓친 결함은 끝에 가면 페이지 400개의 결함이 되고, 나중에 고치는 비용은 처음 실행보다 큽니다.

<a id="cost-control"></a>

## 비용 관리

자료 1,000개를 백필하면 만만치 않은 청구서를 받게 됩니다. 감당할 만한 수준으로 유지하는 방법은 다음과 같습니다.

- **먼저 거릅니다.** 대부분의 아카이브는 절반이 죽은 링크이거나, 저장만 해 놓고 열어 본 적 없는 것들입니다. 무엇이든 인제스트하기 전에 에이전트에게 제목부터 선별하게 합니다.
- **배치 크기에 상한을 두고,** 규모를 키우기 전에 처음 몇 배치에 드는 비용을 지켜봅니다.
- **보관만 할 자료는 건너뜁니다.** 모든 자료에 위키 페이지가 필요하지는 않습니다. 자료를 `raw/`에 두어도 검색은 됩니다.

<a id="dead-links"></a>

## 죽은 링크

오래된 북마크 내보내기 파일에는 더는 존재하지 않는 페이지가 가득합니다. 중간에 알게 되기보다 인제스트하기 전에 확인합니다.

```bash
python3 -c "import sys,urllib.request as u;[print(l.strip()) for l in sys.stdin]"
```

사라졌지만 가치가 있는 자료는 Internet Archive에 사본이 있는 경우가 많습니다. 거기서 클리핑하고, 원본이 죽었다는 사실을 프론트매터에 적어 둡니다. URL이 404를 돌려주는 자료 페이지는 1년 뒤에는 검증할 수 없기 때문입니다.

<a id="resuming"></a>

## 중단된 작업 재개

진행 상황은 하면서 `log.md`에 기록합니다. 배치당 한 줄씩, 다룬 폴더와 범위를 적습니다. 작업이 중간에 멈추는 일은 반드시 생기는데, 그때 어느 파일까지 끝났는지 짐작하는 대신 로그에서 이어 갑니다.

<a id="after-the-backfill"></a>

## 백필 이후

전체 린트를 실행합니다. 대규모 인제스트는 언제나 고아 페이지, 거의 같은 중복 페이지, 깨진 링크를 남깁니다.

```
/lint
```

그런 다음 리뷰를 실행해 볼트에 이제 무엇이 들어 있는지 확인합니다. 백필을 마친 볼트는 저장했다는 사실조차 잊은 것들을 알고 있기 때문입니다. 그 순간이 이 모든 작업의 보람입니다.
