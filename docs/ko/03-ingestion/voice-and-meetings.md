# 음성 메모와 회의

담아 둘 만한 생각은 책상 앞에서 떠오르는 일이 드뭅니다. 걷거나 운전하거나 줄을 서 있을 때 쓸 수 있는 수집 방법은 음성뿐인데, 대부분의 볼트가 끝내 연결하지 않는 방법이기도 합니다.

<a id="capture"></a>

## 수집

녹음 앱은 무엇이든 되고, 파일이 볼트가 닿을 수 있는 곳에 도착하기만 하면 됩니다. 없애야 할 마찰은 전송입니다. 휴대폰에서 볼트로 오디오를 옮기는 데 동작이 하나 넘게 들면 결국 그만두게 됩니다.

가장 단순하고 믿을 만한 구성은 이렇습니다. 휴대폰 기본 앱으로 녹음하고, 클라우드 폴더로 공유하고, 예약 작업이 새 파일을 전사해 `raw/`에 넣게 합니다.

Obsidian 모바일 앱은 볼트에 바로 녹음할 수 있어서, 이미 모바일을 동기화하고 있다면 전송 단계가 통째로 사라집니다.

<a id="transcription"></a>

## 전사

Whisper는 로컬에서 돌아가며, 팔 길이 거리에서 녹음한 음성 메모에는 충분히 쓸 만합니다. 다른 자료보다 여기서 로컬이 더 중요한데, 음성 메모에는 덜 여문 생각이, 회의 녹음에는 다른 사람의 말이 담겨 있기 때문입니다.

이름과 기술 용어는 틀리게 나올 것으로 예상합니다. 나중이 아니라 인제스트할 때, 무슨 말을 했는지 아직 기억할 때 바로잡습니다.

<a id="voice-notes-are-drafts-not-sources"></a>

## 자료가 아니라 초안인 음성 메모

음성 메모는 소리 내어 생각하는 과정이라, 헛다리 짚은 시작과 끝맺지 못한 문장이 들어 있습니다. 그대로 인제스트하면 앞뒤가 맞지 않는 자료 페이지가 나옵니다.

트랜스크립트를 아이디어 하나를 뽑아낼 원재료로 다룹니다.

```
This is a voice note, my own thinking out loud. Extract the actual idea, drop
the false starts and repetition, and write it as one short concept page in my
words. If there are two unrelated ideas, make two pages. Keep the recording date.
```

<a id="meetings"></a>

## 회의

회의에서 간직할 만한 것은 세 가지이고, 그렇지 않은 것이 압도적으로 많습니다. 결정, 담당자가 있는 약속, 열려 있는 질문입니다.

```
This is a meeting transcript. Extract decisions made, commitments with who owns
each one, and open questions. Link every person mentioned to their entity page.
Skip discussion that did not lead anywhere.
```

약속은 위키가 아니라 해당 프로젝트의 `Inputs/`로 보냅니다. 약속은 지식이 아니라 일이며, 일주일이면 낡습니다. [두 계층](../01-concepts/two-layers.md) 페이지에서 이 분리가 왜 중요한지 다룹니다.

<a id="consent-and-other-people"></a>

## 동의와 다른 사람들

다른 사람을 녹음하는 일에는 관할 지역마다 다른 법적 요건이 있으며, 형식적인 절차가 아닙니다. 참석자 전원의 동의를 요구하는 곳도 있습니다.

합법성과는 별개로, 회의 트랜스크립트에는 다른 사람들이 경계를 풀고 한 말이 들어 있습니다. 공유할 수 있는 볼트에는 그런 내용을 넣지 않고, 애초에 그 회의가 지식 계층에 들어가야 하는지, 추려 낸 결정 세 건으로 충분하지 않은지 생각해 봅니다.
