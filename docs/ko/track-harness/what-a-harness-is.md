# 하네스란 무엇인가

하네스는 텍스트 예측을 실제 작업으로 바꿔 주는, 모델을 둘러싼 모든 것입니다. 루프, 도구, 프롬프트, 권한, 배관이 여기에 들어갑니다. 모델은 결정하고, 하네스는 실행하고 관찰하고 결과를 다시 모델에 돌려줍니다. 같은 모델이라도 하네스가 다르면 전혀 다른 에이전트가 됩니다.

<a id="the-loop"></a>

## 루프

중심에는 while 루프가 있습니다. 대화를 모델에 보냅니다. 응답에 도구 호출이 들어 있으면 실행하고, 결과를 덧붙이고, 다시 돕니다. 텍스트만 들어 있으면 멈추고 사용자에게 보여 줍니다. 요령은 이것이 전부입니다. Thorsten Ball의 [How to build an agent](https://ampcode.com/notes/how-to-build-an-agent)는 400줄이 채 안 되는 Go 코드로 이를 구현합니다. 이 핸드북의 나머지는 모두 이 루프를 다듬는 이야기입니다.

<a id="tool-schemas"></a>

## 도구 스키마

도구는 모델이 읽는 JSON 스키마입니다. 이름, 설명, 타입이 붙은 매개변수로 이뤄집니다. 설명은 변장한 프롬프트입니다. 모델은 설명을 읽고 도구를 고르므로, 설명이 모호하면 동작도 모호해집니다. 전송 방식보다 세분화 수준, 이름 짓기, 오류 메시지가 더 중요합니다. 자세한 내용은 [도구와 MCP](tools-and-mcp.md)에서 다룹니다.

<a id="system-prompt"></a>

## 시스템 프롬프트

상시 적용되는 지시입니다. 에이전트가 누구인지, 어떻게 행동해야 하는지, 환경이 어떻게 생겼는지를 적습니다. 프로덕션 하네스는 수천 단어에 이르는 시스템 프롬프트를 싣습니다. 하우스 스타일, 안전 규칙, 도구 사용 규약 같은 것들입니다. "그저 챗봇"이 "판단력 있는 에이전트"가 되는 곳이 바로 여기입니다.

<a id="permissions"></a>

## 권한

`rm -rf`를 실행할 수 있는 에이전트에는 게이트가 필요합니다. 하네스는 모델의 의도와 기계 사이에 허용 목록, 도구별 승인 프롬프트, 샌드박스, 읽기 전용 모드를 겹겹이 둡니다. 권한 시스템이 있어야 에이전트를 지켜보지 않고 맡겨 둘 수 있습니다. 없다면 사용자가 곧 하네스입니다.

<a id="context-window-management"></a>

## 컨텍스트 윈도 관리

윈도는 유한하고, 가득 차기 전에 품질이 먼저 떨어집니다. 무엇이 윈도에 들어갈지는 하네스가 정합니다. 어떤 파일을 넣을지, 도구 출력을 얼마나 넣을지, 지난 턴을 언제 요약할지, 세션을 넘어 메모리 파일에 무엇을 남길지입니다. 이것이 [컨텍스트 엔지니어링](context-engineering.md)이라는 분야이며, 좋은 하네스가 제값을 하는 곳입니다.

<a id="why-the-harness-matters-as-much-as-the-model"></a>

## 하네스가 모델만큼 중요한 이유

2026년까지의 벤치마크는 같은 사실을 거듭 보여 줍니다. 숫자를 움직이는 것은 하네스입니다. Databricks의 내부 테스트에서는 pi의 최소 하네스가 더 무거운 하네스보다 통과율이 높았고, 턴당 컨텍스트는 3분의 1만 썼습니다. 모델은 같고 장치만 달랐습니다. 부풀린 컨텍스트를 보내는 하네스는 돈을 낭비하고 추론을 떨어뜨립니다. 실패한 도구 호출에서 잘 회복하는 하네스는 다른 하네스가 포기한 작업을 끝냅니다. 이제 모델 연구소들은 하네스를 자사 모델에 맞춰 튜닝합니다(OpenAI는 자사 하네스를 "in-distribution"이라 부릅니다). 하네스를 포장이 아니라 제품의 일부로 본다는 뜻입니다.

<a id="the-rest-of-the-anatomy"></a>

## 나머지 구성 요소

성숙한 하네스는 훅(생명주기 이벤트에서 실행되는 결정적 스크립트), 서브에이전트(위임한 작업에 새 컨텍스트 윈도를 주는 장치), 스킬(필요할 때 불러오는 지시)을 더합니다. [Claude Code](claude-code-as-harness.md)는 이 모두의 참조 구현이고, [지형 페이지](harness-landscape.md)에서 대안들을 살펴봅니다.

구성 요소를 한 번 익혀 두면 어떤 프레임워크든 읽힙니다. 모두 같은 루프가 다른 외투를 입고 있을 뿐입니다.
