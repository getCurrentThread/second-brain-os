# 실습: 졸업 시점 알기

이제 모든 하네스가 하는 일을 하는 약 150줄이 손에 있습니다. 루프, 실행, 게이트, 예산, 종료입니다. 만드는 과정이 곧 공부였습니다. 이 페이지는 졸업 면담입니다. 그 줄들에 무엇이 없는지, 각 빈틈을 기성품이 어떻게 메우는지, 고를 때 쓸 솔직한 규칙을 다룹니다.

아래 비교는 [Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview)를 기준으로 합니다. Claude Code의 장치를 그대로 라이브러리로 만든 것이라, 이 실습에서 올라갈 자연스러운 경로이기 때문입니다. 대안은 [지형 페이지](harness-landscape.md)에서 다룹니다.

<a id="gap-one-compaction-quality"></a>

## 빈틈 1: 압축 품질

예산 처리는 오래된 턴을 버리고 한 줄 요지만 남깁니다. 그러면 결정, 파일 경로, 반쯤 끝난 논의가 사라집니다. 바로 남겨 둘 가치가 있는 것들입니다. Agent SDK는 Claude Code의 자동 컨텍스트 관리를 물려받습니다. 트랜스크립트를 제대로 요약하는 압축이어서, 부피 큰 도구 출력은 덜어 내고 의도는 보존하며, 무엇을 남길지는 훅으로 제어합니다. 요지와 좋은 요약의 차이는 작업을 이어 가는 에이전트와 같은 일을 되풀이하는 에이전트의 차이이며, 그 이유는 [컨텍스트 엔지니어링](context-engineering.md)이 설명합니다.

<a id="gap-two-parallel-tool-execution"></a>

## 빈틈 2: 병렬 도구 실행

현재 모델은 한 턴에 `tool_use` 블록 여러 개를 돌려주는 일이 흔합니다. 이 루프는 그것을 차례로 실행합니다. 옳지만 느립니다. 30초짜리 명령 세 개면 90초가 걸립니다. SDK는 서로 독립적인 도구 호출을 동시에 실행하고, 같은 발상의 더 큰 버전으로 서브에이전트를 더합니다. 새 컨텍스트 윈도에서 위임한 작업을 하고, 최종 보고서만 부모에게 돌려주는 방식입니다.

<a id="gap-three-sandboxing"></a>

## 빈틈 3: 샌드박싱

2부는 이 게이트가 허술하다고 인정했습니다. 접두어 일치는 셸 메타문자를 그냥 통과시키고, `input()`은 사용자가 지켜보는 동안에만 작동합니다. SDK는 [하네스로서의 Claude Code](claude-code-as-harness.md)에서 설명한 완전한 권한 시스템을 갖추고 있습니다. 설정의 허용 목록 규칙, 권한 모드, 샌드박스 명령 실행, 그리고 확률적이 아니라 결정론적으로 차단하는 `PreToolUse` 훅입니다. 정책을 코드로 강제하는 것이지, 사용자가 키보드 앞에 있어 주기를 바라는 것이 아닙니다.

<a id="gap-four-resume"></a>

## 빈틈 4: 재개

작업 도중에 에이전트를 죽이면 모든 것이 사라집니다. 트랜스크립트가 Python 리스트에만 있었기 때문입니다. SDK의 세션은 여러 차례 주고받는 동안 상태를 유지하고, 나중에 대화를 재개하거나 포크할 수 있게 해 줍니다. `.claude/`에서 불러오는 메모리 파일과 합치면, 에이전트는 세션마다 프로젝트를 다시 알아내는 대신 이미 아는 채로 시작합니다.

<a id="the-decision-rule"></a>

## 결정 규칙

다음 중 하나 이상에 해당하면 직접 만드십시오. 배우는 중일 때(이 핸드북이 있는 이유입니다). 루프 자체가 제품이라 모든 줄을 직접 쥐고 있어야 할 때. 또는 작업이 충분히 좁아서(도구 두세 개, 짧은 세션, 곁에 있는 사람) 150줄로 정말 다 덮일 때. 쓸모 있는 사내 도구 상당수가 그 크기로 잘 살고 있습니다.

다음 중 어느 하나라도 해당하는 순간 하네스를 채택하십시오. 에이전트가 사람 없이 돌 때. 신뢰할 수 없는 콘텐츠(웹 페이지, 이메일, 남의 코드)를 읽을 때. 세션이 길어서 압축 품질이 성패를 가를 때. 권한 시스템을 본격적으로 만들고 있는 자신을 발견했을 때. 이 각각은 Anthropic을 비롯한 곳들이 이미 해 놓았고, 아직 만나 보지 못한 실패 모드에 대해 시험까지 마친, 몇 달치의 눈에 띄지 않는 엔지니어링입니다. 다시 만드는 것은 엄밀함이 아니라 비용입니다.

솔직한 요약은 이렇습니다. 150줄은 목적지였던 적이 없습니다. 이 줄들 덕분에 이제 프레임워크 문서가 마법이 아니라 선택지로 읽힙니다. 벌거벗은 루프가 어떻게 생겼는지 알기 때문에, 어떤 외투가 따뜻하고 어떤 것이 장식인지 구분할 수 있습니다. [지형](harness-landscape.md)에서 하나를 고르고, 실제 작업을 연결하고, 계속 트랜스크립트를 읽으십시오.
