# 패턴

루프의 모양 다섯 가지가 이름만 바꿔 가며 되풀이해서 나타납니다. 각각 특정 종류의 작업에서 제값을 하고, 각각 옹호자들이 슬쩍 넘기곤 하는 실패 모드가 있습니다. 여기에는 둘 다 적었습니다.

<a id="run-in-a-loop-ralph"></a>

## 루프로 계속 돌리기(Ralph)

Geoffrey Huntley가 2025년 7월에 내놓은 원조는 `while :; do cat PROMPT.md | claude-code ; done`입니다. 오케스트레이션이 전혀 없습니다. 세션이 끝나면 다른 세션이 처음부터 시작해서 같은 프롬프트 파일과 같은 저장소를 읽고, 디스크의 파일을 통해 지난 세션이 멈춘 곳에서 이어받습니다. 새 컨텍스트와 영속 파일이, 길어질수록 나빠지는 하나의 긴 세션을 이긴다는 사실을 가장 순수하게 보여 줍니다. Anthropic은 이제 이것을 Claude Code 저장소의 `ralph-wiggum` 플러그인으로 제공합니다.

실패 모드는 저자 스스로 인정한 것들입니다. 컴파일러만 만족시키고 다른 것은 만족시키지 않는 자리표시자 구현, 일어나 보면 빌드되지 않는 트리, 그리고 처음부터 새로 만드는 작업에 어울린다는 점입니다. Huntley 본인의 말로는 기존 코드베이스에는 Ralph를 돌리지 않을 것이라고 합니다. Ralph로 첫 버전의 90% 정도에 닿을 수 있지만, 유일한 브레이크는 사람이 누르는 정지 버튼입니다.

<a id="plan-execute-verify"></a>

## 계획-실행-검증

실행을 단계로 나눕니다. 한 패스가 계획 파일을 만들고, 이어지는 패스가 단계를 실행하며, 검증기가 단계마다 게이트 역할을 합니다. 프롬프트 하나로는 방향이 흐트러지는 다단계 작업에 좋습니다. 실패 모드는 계획이 현실과 부딪히는 순간 낡아 버린다는 것입니다. 낡은 계획을 충실히 실행하는 루프는 오류를 키우므로, 검증기는 끝에서 한 번이 아니라 단계마다 돌아야 합니다.

<a id="generator-critic-pairs"></a>

## 생성자-크리틱 쌍

한 에이전트가 만들고, 별도의 패스가 좁은 루브릭에 따라 판정하고, 결함이 다음 시도로 이어집니다. 만드는 쪽과 체커의 분리가 핵심입니다. 구현자는 자신을 채점할 수 없습니다. 실패 모드는 두 가지입니다. 모호한 루브릭은 크리틱을 소음 발생기로 만듭니다. 그리고 생성자와 크리틱이 모델과 컨텍스트를 공유하면 사각지대도 공유해서 서로를 승인하는 쪽으로 수렴합니다. 자세한 내용은 [크리틱과 검증](critics-and-verification.md)에, 구성 방법은 [실습: 크리틱](build-critic.md)에 있습니다.

<a id="tournament-best-of-n"></a>

## 토너먼트 / best-of-n

시도 n개를 병렬로 띄우고(git 워크트리를 쓰면 격리가 값쌉니다) 검증기가 승자를 고르게 합니다. 시도마다 편차가 크고 검증이 싸다면 강력합니다. 실패 모드는 시도가 쓸 만하든 아니든 비용이 n배가 된다는 것입니다. 그리고 진짜로 강한 선별기가 없다면 자신만만한 쓰레기에 n번 값을 치르고 그중 가장 자신만만한 것을 고른 셈이 됩니다. 이 패턴을 감당할 수 있는지는 검증기 비대칭 시험이 결정합니다.

<a id="overnight-unattended-runs-with-mailbox-reports"></a>

## 우편함 보고서를 남기는 야간 무인 실행

예산을 걸고, 래칫을 두고, 브랜치로 격리한 실행입니다. 자는 동안 일하고, 무엇이 나아졌는지, 무엇이 루프를 멈췄는지, 어떤 결정이 필요한지를 적은 아침 보고서를 마크다운으로 남깁니다. 이 규율의 최종 형태이자 진입 요건이 가장 엄격한 패턴입니다. [종료 조건](stop-conditions.md)의 모든 브레이크에 더해 최악의 경우도 평범하게 만드는 가드레일이 필요합니다. 실패 모드는 이렇습니다. 지켜보는 사람이 없는 루프는 지켜보는 사람 없이 실수를 저지르고, 그 빚은 이해 부채의 형태로 당신에게 떨어집니다. 배포된 변경이 그것에 대한 이해보다 앞서가는 것입니다. Osmani의 경고는 여전히 유효합니다. 루프는 시작 버튼만 누르는 사람이 아니라 계속 엔지니어로 남을 사람처럼 만드십시오.

<a id="choosing-between-them"></a>

## 고르는 법

진짜 검증기가 있는 가장 단순한 루프에서 시작하십시오. [실습: 목표 테스트](build-goal-test.md)의 평범한 재시도 루프입니다. 통과하지만 볼품없는 결과가 흔한 실패가 되면 크리틱을 더하십시오. 단일 루프가 매번 알아보기 쉽게 멈추게 된 뒤에야 병렬이나 야간 실행으로 가십시오. 화려한 패턴은 이미 갖춘 규율을 증폭하고, 규율이 없다는 사실도 증폭합니다.
