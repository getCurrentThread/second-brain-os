# 컨텍스트 실습

원리와 [네 곳](the-four-places.md)은 이미 알고 있습니다. 이 페이지는 실습 시간입니다. 기존 에이전트를 감사하고, 구조를 다시 짜고, 일정 규모를 넘으면 중요해지는 두 가지 개선을 더합니다.


> 아래 감사 전체는 스킬로도 패키지되어 있습니다. [강좌 플러그인](../../../plugins/README.md)을 설치하고 프로젝트에서 `/agents-course:context-audit`를 실행하십시오.

<a id="audit-the-window"></a>

## 윈도 감사

기억에 의존하지 말고 실제 에이전트를 놓고 하십시오.

1. 요청 페이로드 하나를 통째로 수집합니다. 대화 중반의 한 턴에서 프레임워크가 모델에 보내는 JSON을 그대로 기록하십시오.
2. 각 부분의 토큰 수를 따로 셉니다. 시스템 프롬프트, 도구 정의, 메시지 히스토리, 검색된 내용, 현재 질의입니다. 숫자 다섯 개를 적어 두십시오.
3. 시스템 프롬프트 안의 동적 값을 모두 동그라미 칩니다. 타임스탬프, 사용자 이름, 주입된 메모리가 해당합니다. 하나하나가 호출마다 확실한 캐시 미스입니다.
4. 도구 목록이 1턴과 20턴에서 같은지 확인합니다. 실행 중에 바뀌었다면 그때마다 캐시 전체 무효화 비용을 치른 것입니다.
5. 히스토리에서 가장 큰 항목 하나를 찾습니다. 거의 언제나 원문 그대로 들어온 도구 결과이며, 파일 경로였어야 할 것입니다.
6. 현재 목표가 어디 있는지 찾습니다. 첫 메시지에만 나온다면 지금은 윈도의 약한 가운데에 놓여 있는 것입니다.
7. API 응답에서 `cache_read_input_tokens`를 읽습니다. 캐시가 이미 데워진 대화에서 0이면 프리픽스의 무언가가 바뀌고 있다는 뜻입니다.

<a id="restructure-to-the-four-places"></a>

## 네 곳으로 재구성

감사에서 찾은 문제를 순서대로 처리합니다. 시스템 프롬프트에는 모든 호출에서 참인 것만 남기고, 동그라미 친 동적 값은 모두 메시지 히스토리로 옮깁니다. 도구 목록은 대화 시작 시점에 고정하고, 실행 중에 도구를 빼던 곳은 거절 문자열을 돌려주는 호출 차단으로 바꿉니다. 출력이 큰 도구는 결과를 디스크에 쓰고 경로와 한 줄짜리 영수증만 돌려주도록 고칩니다. 그다음 끝부분을 추가합니다. 도구 결과가 몇 번 쌓일 때마다 현재 목표를 다시 적은 한 줄을 덧붙입니다. 감사를 다시 돌리면 다섯 숫자가 작고 안정된 프리픽스와 그때그때 갱신되는 짧은 끝부분 쪽으로 눈에 띄게 옮겨 가야 합니다.

<a id="switch-to-tool-search-past-twenty"></a>

## 스무 개를 넘으면 도구 검색으로 전환

Anthropic의 [Advanced tool use](https://www.anthropic.com/engineering/advanced-tool-use) 글은 정의를 전부 로드해 두는 방식은 규모가 커지면 통하지 않는다고 보고합니다. 대신 도구 검색을 켜자 자사 MCP 평가에서 Opus 4는 49%에서 74%로, Opus 4.5는 79.5%에서 88.1%로 올랐습니다. 그쪽의 기준은 도구 10개 이상 또는 정의가 10K토큰을 넘을 때이고, 이 강좌는 확실한 선을 스무 개에 긋습니다. 늘 쓰는 작은 핵심 도구만 로드해 두고 나머지는 지연 로드로 표시한 뒤, 모델이 필요할 때 정의를 검색하게 합니다. 프리픽스가 줄고, 위 수치로 보면 선택 정확도도 함께 오릅니다.

<a id="add-a-summarising-subagent"></a>

## 요약 서브에이전트 추가

서브에이전트는 컨텍스트 방화벽입니다. 작업에 파일 쉰 개를 읽어야 한다면 메인 윈도에서 읽지 마십시오. 서브에이전트를 띄우면 그 자신의 윈도가 파일 쉰 개를 받아 내고 한 페이지짜리 요약을 돌려줍니다. 메인 에이전트는 증거가 아니라 결론만 가집니다. 같은 패턴이 대량 읽기 전반에 맞습니다. 로그 뒤지기, 큰 diff, 문서 더미가 그렇습니다. [하네스 핸드북](../track-harness/context-engineering.md)은 방화벽을 실제 환경에 연결하는 방법을 다룹니다.

<a id="tips"></a>

## 팁

- 3~5단계마다 끝부분에 목표를 다시 적습니다.
- 약 2,000토큰을 넘는 도구 결과 원문은 히스토리에 남기지 않습니다. 대신 경로와 영수증을 둡니다.
- 도구는 막되 빼지 않습니다.
- 시스템 프롬프트 변경은 릴리스로 다루고, diff로 비교합니다.
- 프로덕션에서 캐시 지표를 지켜봅니다. 소리 없는 캐시 미스는 10배짜리 청구서입니다.

<a id="prove-it-to-yourself"></a>

## 직접 확인하기

1. 30K토큰짜리 트랜스크립트 한가운데에 지어낸 사실 하나를 심고 그것을 물어봅니다. 그런 다음 같은 사실을 마지막 메시지로 옮기고 다시 물어봅니다. 두 답을 비교하십시오.
2. 똑같은 요청을 두 번 보내고 `cache_read_input_tokens`를 읽습니다. 그다음 시스템 프롬프트 맨 위에 타임스탬프를 넣고 값이 0으로 떨어지는 것을 지켜보십시오.
3. 같은 쉰 개 파일 요약을 한 번은 메인 윈도에서, 한 번은 서브에이전트로 돌립니다. 최종 컨텍스트 크기와 답의 품질을 비교하십시오.
