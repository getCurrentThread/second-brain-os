# 리서치 보고서

리서치 보고서는 질문이 볼트에 지금 있는 것 이상을 필요로 할 때 만드는 것입니다. 볼트는 출발점이지 답의 전부가 아닙니다.

<a id="scope-against-what-exists-first"></a>

## 먼저 이미 있는 것에 맞춰 범위 잡기

```
I need to understand how companies are deploying agent harnesses in production.
What does my vault already cover, what is thin, and what is missing entirely?
```

그 답이 곧 리서치 계획입니다. 좋은 보고서에서 일의 대부분은 찾아보지 않아도 되는 것을 아는 데 있고, 볼트에서 출발하면 작년에 읽은 것을 다시 읽지 않아도 됩니다.

<a id="fill-the-gaps-deliberately"></a>

## 빈틈은 의도적으로 채우기

빈틈을 메울 자료를 찾아 `raw/`를 거쳐 제대로 인제스트하고, 다른 모든 것과 같은 방식으로 페이지를 만들게 하십시오.

지름길을 뿌리치는 것이 중요합니다. 새 글을 보고서 초안에 바로 붙여 넣으면 보고서는 써지지만 볼트는 나아지지 않고, 그러면 인접한 주제의 다음 보고서도 같은 자리에서 출발합니다.

<a id="structure"></a>

## 구조

```
Question
What I found          (with page citations)
Where sources disagree
What I could not establish
What would change the conclusion
```

마지막 두 절이 보고서를 다시 읽을 만하게 만듭니다. 조사 결과만 제시하는 보고서는 더 탄탄해 보이지만 덜 쓸모 있습니다. 독자가 어디가 결론을 떠받치고 어디가 허술한지 알 수 없기 때문입니다.

<a id="store-it-as-a-source"></a>

## 원본 자료로 보관하기

보고서는 `output/`에 두고, 그다음 원본 자료로 다시 인제스트합니다.

보고서는 내 이해를 날짜와 함께 찍어 둔 스냅샷입니다. 이를 볼트에 원본 자료로 두면 나중의 자료가 그것을 슬그머니 대체하는 대신 명시적으로 반박할 수 있습니다. [대체](../04-structuring/contradictions-and-supersession.md)를 보십시오.
