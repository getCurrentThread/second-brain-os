# 스케줄링

예약 실행은 볼트가 살아 있는 것처럼 느끼게 합니다. 아침에 일어나면 볼트가 클리핑해 둔 것을 정리해 넣었고, 모순을 하나 알아챘고, 무엇이 바뀌었는지 세 줄로 남겨 두었습니다.

이것은 노트에 대한 무인 쓰기이기도 하므로 순서가 중요합니다. 먼저 [가드레일](safety-and-guardrails.md)을 제대로 갖추고, 그다음에 예약하십시오.

<a id="cadence-per-job"></a>

## 작업별 주기

**인제스트, 매일.** 밤사이에, 낮 동안 `raw/`에 쌓인 것을 대상으로 합니다. 매일이 맞는 이유는, 묶음으로 처리하면 저장해 둔 세 가지가 같은 생각에 관한 것임을 에이전트가 알아챌 기회가 생기기 때문입니다. 매시간 돌리면 그렇지 않습니다.

**링크, 매주.** 연결하려면 연결할 재료가 있어야 합니다. 일주일치 인제스트 뒤에 돌리십시오.

**린트, 매주.** 링커 다음에 돌려서, 그 패스가 망가뜨린 것을 잡습니다.

**리뷰, 매주.** 실제로 읽게 되는 유일한 출력입니다. 계획을 세우는 날 아침에 맞추십시오.

**지표, 매달.** 노트에 숫자 네 개를 덧붙입니다. [지표](../05-graphs/metrics.md)를 보십시오.

<a id="setting-one-up"></a>

## 하나 설정하기

Claude Desktop에서 Schedule 탭을 열고 새 작업을 만듭니다.

```
Frequency:  Daily, 7:00am
Folder:     your vault
Prompt:     File anything new in raw/ into the wiki following CLAUDE.md.
            Link it to existing pages. Update index.md and log.md. Commit
            with a message naming the run. Then write me three lines on
            what changed.
```

세션에서 요청해도 됩니다. "매일 오전 7시에 raw/를 인제스트하고 바뀐 내용을 요약하는 작업을 설정해 주세요."

터미널에서 `cron`이나 Task Scheduler가 Claude Code를 헤드리스로 호출하는 방식도 똑같이 동작하며, 실행 결과가 자동으로 git 커밋에 들어가게 하고 싶다면 이쪽이 더 낫습니다.

<a id="what-a-run-must-produce"></a>

## 실행이 반드시 만들어 내야 하는 것

매번 세 가지입니다.

**로그 항목.** 없으면 자는 동안 무슨 일이 있었는지 감사할 수 없습니다.

**커밋.** 실행당 하나이며, 메시지에 그 실행의 이름을 적습니다. 이것이 잘못된 실행을 저녁 한나절이 아니라 명령 한 번으로 되돌릴 수 있게 해 줍니다.

**당신에게 가는 보고.** 한 줄이라도 좋습니다. 눈에 보이는 출력이 없는 예약 작업은 신뢰하지 않게 되고, 그다음에는 읽지 않게 됩니다.

<a id="detecting-silent-failure"></a>

## 조용한 실패 알아채기

실패 모드는 충돌이 아닙니다. 실행은 끝났는데 쓸모 있는 일은 하나도 하지 않은 경우입니다. 원본이 비어 있었거나, API 호출이 도중에 실패했거나, 지시문이 어떤 파일과도 맞지 않은 경우입니다.

값싼 점검이 두 가지 있습니다. 실행이 완료만 보고하지 말고 개수를 보고하게 해서, "원본 0건 인제스트"가 눈에 띄게 합니다. 그리고 한 달에 한 번 커밋 빈도를 확인합니다. 매일 도는 작업의 커밋이 일주일 내내 없다면, 화요일부터 조용히 실패하고 있었다는 뜻입니다.

<a id="start-manual"></a>

## 수동으로 시작하기

예약하기 전에 각 작업을 일주일 동안 손으로 돌려 보십시오. 출력이 꼼꼼히 읽지 않고도 받아들일 만큼 좋은지 확인하는 것입니다. 예약한다는 것이 바로 그런 뜻이기 때문입니다.

인제스트는 가장 나중에 예약하십시오. 가장 많이 쓰는 작업입니다.
