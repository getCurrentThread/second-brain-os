# 서브에이전트와 병렬 작업

서브에이전트는 자기만의 컨텍스트로 실행됩니다. 이것이 핵심입니다. 서브에이전트가 질문에 답하려고 페이지 서른 개를 읽어도, 메인 세션의 컨텍스트는 그 서른 페이지가 아니라 답으로만 채워집니다.

<a id="when-to-fan-out"></a>

## 언제 나눠 맡기는가

**여러 페이지에 걸친 조사.** 서브에이전트를 보내 클러스터 하나를 읽고 요약을 들고 돌아오게 합니다. 메인 세션은 실제 작업에 쓸 예산을 지킵니다.

**서로 독립적인 원본 자료.** 관련 없는 글 열 편을 인제스트하는 일은 깔끔하게 병렬로 돌아갑니다. 어느 것도 같은 위키 페이지를 건드리지 않기 때문입니다.

**검증.** 한 에이전트가 쓰고, 다른 에이전트가 페이지를 원본 자료와 대조해 검사합니다. 컨텍스트가 따로이기에 검사가 의미를 갖습니다. 같은 에이전트가 자기 작업을 다시 읽으면 대체로 자기 자신에게 동의합니다.

<a id="when-not-to"></a>

## 언제 그러지 않는가

**관련된 원본 자료.** 같은 주제의 글 세 편은 순차적으로 인제스트해야 합니다. 병렬로 하면 각자 개념 페이지를 따로 만들어 같은 페이지의 버전이 세 개가 되거나, 그중 둘이 덮어써집니다.

**인덱스를 건드리는 모든 일.** `index.md`와 `log.md`는 모든 실행이 덧붙이려 하는 단일 파일입니다. 여기에 병렬로 쓰면 충돌하거나 항목을 조용히 잃습니다.

**작은 일.** 서브에이전트를 띄우려면 컨텍스트를 처음부터 다 세팅하는 비용이 듭니다. 파일 두 개라면 직접 하는 것보다 느립니다.

<a id="merging-parallel-work"></a>

## 병렬 작업 병합하기

충돌 대부분을 피하게 해 주는 규칙은 이렇습니다. 서브에이전트는 서로 겹치지 않는 경로에 쓰고, 부모가 병합합니다.

공유 파일을 직접 쓰게 하지 말고, 각 서브에이전트가 무엇을 쓰려는지 보고하게 하십시오. 부모는 서브에이전트가 모두 돌아온 뒤 인덱스와 로그 갱신을 한 번에 적용합니다. 페이지 파일 자체는, 겹치는 자료를 두 서브에이전트에 준 적이 없다면 병렬로 써도 안전합니다.

병렬 실행 전에는 반드시 커밋하십시오. 잘못되면 한꺼번에 많은 파일에서 잘못되기 때문입니다.

<a id="cost"></a>

## 비용

병렬화는 전체 토큰 사용량을 줄이지 않습니다. 줄이는 것은 실제 소요 시간이고, 지키는 것은 메인 컨텍스트입니다. 서브에이전트 넷의 비용은 대략 하나의 네 배입니다.

이 거래는 대규모 백필에는 값어치가 있고, 클리핑한 글 다섯 편을 매일 인제스트하는 데는 무의미합니다.
