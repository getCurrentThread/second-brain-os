# 가드레일

이 섹션 전체가 기대고 있는 규칙입니다.

**프롬프트가 아니라 열쇠.**

에이전트에게 무언가를 하지 말라고 말하는 것은 선호일 뿐 경계가 아닙니다. 에이전트가 기술적으로 파일을 지우고, 폴더를 비우고, 이메일을 보낼 수 있다면, 언젠가 예상하지 못한 컨텍스트에서 정말로 그렇게 합니다.

무엇이 가능한지는 권한 수준에서 통제하십시오. 그러면 `CLAUDE.md`의 지시문은 경계 위에 놓인 선호가 되고, 노트와 잘못된 실행 사이를 가로막는 유일한 것이 아니게 됩니다.

<a id="scope-write-access"></a>

## 쓰기 권한 좁히기

에이전트에게는 볼트에 대한 쓰기 권한이 필요합니다. 홈 디렉터리에 대한 쓰기 권한은 필요 없으며, 넓은 파일 시스템 권한으로 도는 예약 작업은 작은 편의를 위해 치르는 큰 피해 범위입니다.

커넥터도 같은 원칙입니다. 선택지가 있는 곳에서는 읽기 전용으로 둡니다. 읽기만 되는 캘린더 커넥터는 지시를 아무리 잘못 해석해도 회의를 취소할 수 없습니다.

<a id="never-delete-without-a-record"></a>

## 기록 없이 삭제하지 않기

삭제는 diff를 읽어서는 되돌릴 수 없는 유일한 작업입니다. 내용은 사라지고 부재만 남기 때문입니다.

규칙은 이렇습니다. `log.md`에 그 페이지의 이름과 이유를 적은 줄 없이는 어떤 페이지도 삭제하지 않습니다. 병합도 삭제로 칩니다. 꾸준히 적용하면 사라진 페이지는 언제나 추적할 수 있고, "그 페이지는 어디로 갔지"는 답할 수 없는 질문이 아니게 됩니다.

<a id="git-is-the-real-safety-net"></a>

## 진짜 안전망은 Git

위의 모든 가드레일은 예방용입니다. 그중 하나가 뚫렸을 때 당신을 구해 주는 것은 Git입니다.

대규모로 쓰는 실행 전에는 커밋하십시오. 예약 실행은 자기 작업을 직접 커밋합니다. 그러면 잘못된 인제스트는 `git checkout .` 하나로, 잘못된 병합은 revert 한 번으로 해결됩니다.

예약 실행의 diff를 가끔, 특히 첫 몇 주 동안은 읽으십시오. 에이전트가 오전 7시에 실제로 무엇을 하는지 알게 되는 방법이며, 그것은 으레 짐작과 다릅니다.

<a id="dry-runs"></a>

## 드라이 런

많은 파일을 건드리는 작업은 무엇이든 보고만 하는 모드로 한 번 돌려 보십시오.

```
Do a dry run: list every page you would create, update or delete, and the links
you would add. Write nothing.
```

출력을 읽는 데 1분이 걸리며, 잘못 이해한 지시문이 수정 400건이 되기 전에 잡아냅니다.

<a id="watch-for-scope-creep"></a>

## 범위 확장을 경계하기

에이전트는 일을 늘립니다. 인제스트하라고 하면 관련 없는 페이지를 정리하고, 서식을 고치고, 일관성을 위해 무언가 이름을 바꿀 수도 있습니다. 하나하나는 변명이 되지만, 합치면 모든 것을 읽어 보지 않고는 실행이 무엇을 했는지 알 수 없다는 뜻입니다.

명시적으로 지시하십시오. 요청한 일을 하고, 눈에 띈 다른 사항은 목록으로 알리고, 그 밖에는 아무것도 바꾸지 말라고 하십시오.

<a id="what-not-to-put-in-the-vault"></a>

## 볼트에 넣지 말아야 할 것

자격 증명, API 키, 비밀로 지킬 의무가 있는 모든 것, 다른 사람의 개인 정보입니다.

에이전트가 유출할 것이라서가 아닙니다. 볼트는 동기화되고, 커밋되고, 백업되고, 가끔 공유되는 하나의 파일 트리이기 때문입니다. 사본이 하나 늘 때마다 그 내용이 존재하는 곳이 하나 늘어납니다. [개인정보](../09-maintenance/privacy-and-secrets.md)를 보십시오.
