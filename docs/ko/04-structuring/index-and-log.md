# index.md와 log.md

지식은 아니지만, 이것이 없으면 지식에 닿기 어렵고 감사하기는 불가능한 파일 두 개입니다.

<a id="indexmd"></a>

## index.md

카탈로그입니다. 모든 페이지를 유형별로 묶어 나열하고, 빈틈은 맨 아래에 모아 둡니다.

인덱스의 진짜 역할은 검색 비용을 아끼는 것입니다. 에이전트는 질문을 받으면 먼저 인덱스를 읽어 무엇이 있고 어느 페이지를 열어 볼 만한지 파악합니다. 인덱스가 없다면 대안은 전문 검색으로 훑는 것인데, 더 느리고, 컨텍스트를 더 쓰고, 질문과 표현이 다른 페이지를 놓칩니다.

빠짐없어 보이게 하기보다 탐색하기 쉽게 유지합니다.

```markdown
## Concepts

### Retrieval
- [[Retrieval augmented generation]] - chunking, embeddings, when it beats a wiki
- [[GraphRAG]] - entity graph plus community summaries

### Agents
- [[Agent harness]] - the loop around a model
```

항목마다 설명은 한 줄입니다. 그 한 줄이 에이전트가 페이지를 열지 말지 판단하게 해 주며, 토큰을 쓸 만한 가치가 있습니다.

<a id="gaps"></a>

## 빈틈

인덱스 맨 아래에, 링크는 걸려 있지만 존재하지 않는 페이지를 모읍니다.

이 절은 볼트에서 가장 바로 행동에 옮길 수 있는 부분입니다. 내 자료가 계속 언급하는데 한 번도 적어 두지 않은 것의 목록이고, 대개 다음에 무엇을 읽어야 하는지 알려 주는 정확한 지도입니다.

<a id="logmd"></a>

## log.md

작업 하나에 한 줄씩 뒤에 덧붙여 쓰며, 최신 항목이 맨 아래에 옵니다.

```
2026-09-07 ingest raw/karpathy-gist.md -> 1 source, 2 concepts, 1 entity, 9 links
2026-09-07 merge [[RAG]] <- [[Retrieval-augmented generation]]
2026-09-08 lint -> 3 broken links fixed, 2 orphans flagged
```

로그는 에이전트가 관리하는 볼트를 감사할 수 있게 만듭니다. 페이지가 낯선 내용을 말하고 있을 때, 로그가 어느 실행에서 나온 것인지 알려 줍니다. 무언가 사라졌을 때, 로그는 추적 가능한 병합과 영문 모를 실종을 가르는 차이입니다.

로그는 [리뷰 스킬](../../../skills/README.md)에도 원재료를 줍니다. 이번 주에 무엇이 바뀌었는지는 파일 타임스탬프를 짐작하는 대신 여기서 가져옵니다.

<a id="keeping-both-from-bloating"></a>

## 둘 다 부풀지 않게 하기

인덱스는 볼트와 함께 커지는데 그것은 괜찮지만, 평면 목록은 항목이 200개 언저리를 넘으면 탐색하기 어려워집니다. 주제별로 묶고, 한 주제의 항목이 약 30개를 넘으면 그 주제에 자기 인덱스 페이지를 주고 메인 인덱스에서 링크합니다.

로그는 끝없이 커지고 오래된 항목은 아무도 읽지 않습니다. 몇 달 지난 항목은 달마다 요약 한 줄로 말아 넣거나 날짜가 붙은 파일로 아카이브합니다. 최근 것은 상세하게 두고, 지난 이력은 압축합니다.

<a id="the-rule-that-matters"></a>

## 중요한 규칙

두 파일 모두 자신이 기술하는 작업과 같은 실행에서 갱신합니다.

뒤처진 인덱스는 인덱스가 없는 것보다 나쁩니다. 에이전트가 그것을 믿고, 목록에 없는 페이지는 더 찾지 않기 때문입니다. 나중에 쓴 로그는 기록이 아니라 재구성입니다.
