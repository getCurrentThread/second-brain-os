# 중복 제거와 병합

중복은 피할 수 없습니다. 두 자료가 같은 아이디어를 다른 말로 표현하고, 별칭이 빠져 있고, 볼트에 그 개념이 생기기 전에 일괄 가져오기가 돌았습니다. 문제는 중복을 완전히 막는 방법이 아니라, 둘 다 링크를 쌓기 전에 잡아내는 방법입니다.

<a id="finding-them"></a>

## 중복 찾기

신뢰할 수 있는 순서대로 신호를 꼽으면 다음과 같습니다.

- **비슷한 제목.** 확인하는 비용이 낮고, 복수형과 약어로 생긴 중복을 잡아냅니다.
- **겹치는 별칭.** 두 페이지가 같은 별칭을 내세우면 언제나 버그입니다.
- **공통 백링크.** 같은 자료 다섯 개가 모두 링크하는 두 페이지는 대개 하나의 페이지입니다.
- **내용 유사도.** 비용이 크지만, 이름이 무관해 보이는 경우까지 잡아냅니다.

`second-brain-lint`는 앞의 세 가지를 검사하고 병합을 제안합니다. 병합을 직접 수행하지는 않으며, 이는 의도된 설계입니다.

<a id="why-merging-is-not-automatic"></a>

## 병합이 자동이 아닌 이유

병합은 실질적으로 되돌릴 수 없습니다. 두 페이지가 하나가 되고 나면 어느 주장이 어디서 왔는지 구별할 수 없고, "이 둘은 같은 것이다"라는 에이전트의 판단이야말로 틀리기 쉬운 판단이기 때문입니다.

요약만 보면 똑같아 보이는 두 아이디어는 흔히 일반 사례와 특수 사례이며, 병합하면 그 구분이 영구히 사라집니다.

그래서 에이전트가 제안하고, 결정은 사람이 합니다. 병합 하나를 검토하는 데는 15초면 됩니다.

<a id="the-procedure"></a>

## 절차

병합을 승인하면 다음 순서로 진행합니다.

1. **남길 페이지를 고릅니다.** 더 긴 쪽이 아니라 정식 이름을 기준으로 합니다.
2. **내용을 병합합니다.** 각 주장은 출처와 함께 남깁니다. 겹치는 주장은 하나로 합치고, 엇갈리는 주장은 둘 다 남깁니다.
3. **별칭을 병합합니다.** 사라지는 페이지의 제목도 남는 페이지의 별칭으로 넣습니다.
4. **백링크를 남는 페이지로 옮깁니다.**
5. **옛 경로에 스텁을 남깁니다.** 볼트 밖에서 링크된 적이 있을 때만 남기고, 그렇지 않으면 삭제합니다.
6. **`log.md`에 기록합니다.** 두 이름을 모두 적어, 사라진 페이지를 추적할 수 있게 합니다.

6단계는 에이전트가 건너뛰는 단계이자 나중에 꼭 필요해지는 단계입니다. 기록 없이 사라진 페이지는 실수로 삭제된 페이지와 구별되지 않습니다.

<a id="do-not-dedupe-live"></a>

## 인제스트 도중에는 중복 제거하지 않기

인제스트 도중에 병합하면 에이전트가 볼트에 내용을 더하는 동시에 구조를 바꾸는 셈이어서, 잘못된 병합이 멀쩡한 작업 한가운데에 끼어듭니다.

중복 제거는 독립된 단계로, 매주 또는 일괄 가져오기 뒤에, 깨끗한 git 상태에서 실행합니다. 그러면 잘못된 병합도 `git checkout` 한 번이면 되돌릴 수 있습니다.
