# 한 페이지, 한 아이디어

페이지 하나는 아이디어 하나를 담고, 원본 자료를 본 적 없는 사람도 이해할 수 있을 만큼 잘 설명합니다.

이 규칙은 검색이 동작하는 방식 때문에 존재합니다. 에이전트는 질문에 답할 때 페이지를 통째로 끌어옵니다. 주제 네 개를 다루는 페이지는 건드릴 때마다 상관없는 세 주제를 컨텍스트로 끌고 들어옵니다. 하나만 다루는 페이지는 정확하게 링크되고, 정확하게 검색되며, 부수 피해 없이 갱신됩니다.

<a id="what-atomic-means-here"></a>

## 여기서 원자적이라는 것

짧다는 뜻이 아닙니다. 개념 페이지는 수백 단어가 될 수도 있습니다. 원자적이라는 것은 주제가 하나여서, "와"나 "그리고" 없이 정확한 제목을 붙일 수 있다는 뜻입니다.

제목에 "와"가 필요하거나 페이지에 서로 무관한 주제를 다루는 절 제목이 있다면, 그것은 페이지 두 개입니다.

<a id="splitting-a-source"></a>

## 자료 쪼개기

글 하나에서는 보통 자기 페이지를 가질 만한 개념이 한 개에서 세 개 나오고, 거기에 글 자체가 한 말을 기록하는 자료 페이지가 더해집니다.

자기 페이지를 가질 만한지 가르는 시험은 이것입니다. 이 자료 하나를 다시 가리키지 않고도 설명할 수 있는가? "이 글이 주장한 것"으로서만 의미가 있는 아이디어는 자료 페이지 안에 둡니다. 다른 자료에도 되풀이해 나올 아이디어는 자기 페이지가 필요합니다. 다른 자료들이 거기에 붙게 되기 때문입니다.

<a id="the-failure-in-both-directions"></a>

## 양쪽 방향의 실패

**과도하게 쪼개면** 글 하나에서 페이지 열 개가 나오는데, 하나하나가 문단을 되풀이한 것에 불과하고 저마다 원본 자료로만 거슬러 링크합니다. 그래프는 빽빽해 보이지만 아무 말도 하지 않습니다. 쪼개는 일이 철저함처럼 느껴지기 때문에, 에이전트에게서는 이쪽 실패가 더 흔합니다.

**덜 쪼개면** 자료 페이지가 글 요약이 되고 개념이 하나도 없는 위키가 됩니다. 검색할 수 있는 아카이브가 남는데, 그것은 이미 가지고 있던 것입니다.

확신이 없다면 페이지를 적게 씁니다. 나중에 병합하는 것은 값싸지만, 조각 100개를 풀어내는 것은 그렇지 않습니다.

<a id="length"></a>

## 길이

약 80단어 미만의 개념 페이지는 대개 효율적인 페이지가 아니라 실패한 스텁입니다. 자료가 그 내용을 실제로 다루지 않았거나, 에이전트가 포기한 것입니다. 둘 다 린트 때 잡아낼 만합니다.

약 1,000단어를 넘는 페이지는 대개 아이디어 두 개가 함께 자란 것입니다. 읽으면서 이음매를 찾아봅니다.
