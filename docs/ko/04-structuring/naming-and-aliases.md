# 이름 짓기와 별칭

위키링크는 이름으로 연결되므로, 이름은 겉치레가 아닙니다. 그래프 전체가 그 위에 지어지는 키입니다.

<a id="canonical-titles"></a>

## 정식 제목

페이지 하나에 정식 제목 하나이며, 그 분야 사람과 이야기할 때 쓸 이름으로 정합니다.

대부분의 고생을 피하게 해 주는 실용 규칙은 다음과 같습니다.

- **복수형이 아닌 단수형.** `Vector database`이지 `Vector databases`가 아닙니다.
- **약어는 제목에서 풀어 쓰고, 약어는 별칭에 넣습니다.** 제목은 독자를 위한 것이고, 별칭은 링크를 위한 것입니다.
- **제목에 날짜와 버전을 넣지 않습니다.** 대상이 진짜 버전인 경우는 예외입니다. `MCP spec 2026-07`이라는 페이지는 한 달 뒤면 틀린 페이지가 되지만, 버전 이력을 가진 `MCP`라는 페이지는 그렇지 않습니다.
- **볼트 전용 접두사를 쓰지 않습니다.** `Concept - RAG`는 얻는 것 없이 링크 문법과 충돌합니다.

<a id="aliases"></a>

## 별칭

같은 대상을 부르는 모든 이름을 프론트매터에 나열합니다.

```yaml
title: Retrieval augmented generation
aliases: [RAG, retrieval-augmented generation]
```

별칭은 볼트가 한 가지에 페이지 셋을 조용히 키워 가는 것을 막아 줍니다. 별칭이 없으면 RAG라고 쓴 자료는 `RAG`를 만들고, 풀어 쓴 자료는 두 번째 페이지를 만들며, 둘은 서로의 존재를 모릅니다.

별칭은 나중이 아니라 만들 때 추가합니다. 중복을 알아챌 즈음에는 두 페이지 모두에 이미 백링크가 달려 있습니다.

<a id="two-things-with-the-same-name"></a>

## 이름이 같은 두 대상

제목에서 구분하되, 아무도 입력하지 않을 접미사는 쓰지 않습니다.

```
Mercury (planet)
Mercury (element)
```

그다음 맨 단어를 볼트에서 더 우세한 쪽의 별칭으로 걸거나, 둘 다 중요하다면 어느 쪽에도 걸지 않습니다. 그러면 에이전트가 추측하지 않고 명시적으로 고르게 됩니다.

같은 규칙이 이름이 같은 사람, 그리고 유명한 제품과 이름이 겹치는 내 프로젝트에도 적용됩니다.

<a id="renaming"></a>

## 이름 바꾸기

앱 안에서 이름을 바꾸면 Obsidian이 링크를 갱신합니다. 에이전트가 파일을 직접 바꾸면 갱신되지 않으며, 이것이 에이전트가 관리하는 볼트에서 깨진 링크가 생기는 가장 흔한 단 하나의 원인입니다.

`CLAUDE.md`에 넣을 규칙은 이렇습니다. 이름 바꾸기는 문서화된 절차를 거칩니다. 파일을 갱신하고, 들어오는 링크를 모두 갱신하고, 옛 이름을 별칭으로 추가하고, `log.md`에 기록합니다. 별칭이 중요한 이유는 외부 참조와 내 기억이 계속 통하게 하기 때문입니다.

그런 다음 `scripts/link_check.py`를 실행해 매달린 링크가 없는지 확인합니다.
