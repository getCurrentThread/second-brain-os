# 링크 규칙

이 구조의 가치는 전부 링크에서 나옵니다. 링크가 없으면 파일 이름만 좋은 파일이 담긴 폴더, 즉 검색 인덱스가 남는데, 검색 인덱스는 이미 있습니다.

<a id="the-rule"></a>

## 규칙

모든 페이지에서, 개념이나 엔티티가 처음 나올 때 링크를 겁니다.

이게 전부입니다. 일관되게 적용하면 따로 링크 작업 단계도, 정기 유지보수 절차도 없이 그래프가 저절로 만들어집니다.

<a id="link-do-not-restate"></a>

## 다시 설명하지 말고 링크하기

설명하려는 대상에 이미 페이지가 있다면 링크를 걸고 넘어갑니다.

이렇게 해야 지식이 한 곳에 모입니다. 개념의 설명이 조금씩 다른 네 가지 버전으로 페이지 네 곳에 흩어져 있으면, 갱신하려면 넷을 모두 찾아야 하는데 그렇게 하지 못합니다. 링크로 연결하면 한 번만 존재하고 한 번만 개선됩니다.

<a id="both-directions"></a>

## 양방향

새 페이지는 자신이 참조하는 대상으로 링크를 겁니다. 참조된 페이지도 새 페이지로 되돌아오는 링크를 겁니다.

단방향 링크는 볼트를 참조하지만 볼트가 결코 닿지 못하는 페이지를 낳습니다. 페이지는 존재하고 내용도 정확하지만, 어디서도 찾아지지 않습니다. Obsidian은 링크되지 않은 백링크를 보여 주어 이런 페이지를 찾도록 돕지만, 그 고리는 사람에게 맡기지 말고 에이전트가 인제스트할 때 닫아야 합니다.

<a id="links-that-do-not-exist-yet"></a>

## 아직 존재하지 않는 링크

그래도 링크는 씁니다. 그런 다음 같은 실행에서 대상 페이지를 만들거나, `index.md`의 빈틈(Gaps) 절에 기록합니다.

빈틈은 유용한 정보입니다. 자료 세 곳이 링크했는데 아직 존재하지 않는 페이지는, 바로 다음에 써야 할 것이거나 바로 가서 읽어야 할 것입니다.

받아들일 수 없는 것은 영구적인 빈틈입니다. 결코 존재하지 않을 페이지로 가는 링크는 그래프가 실제보다 많은 것을 다루는 것처럼 보이게 만듭니다.

<a id="how-many"></a>

## 몇 개가 적당한가

목표 숫자는 없지만 모양은 중요합니다. 나가는 링크가 없는 페이지는 막다른 길입니다. 링크가 40개인 페이지는 대개 페이지인 척하는 목록입니다.

한 페이지가 아니라 볼트 전체의 평균을 지켜봅니다. 페이지당 링크가 대략 두 개 미만이면, 그래프는 개별 페이지가 답하지 못하는 것에 답할 만큼 충분히 이어져 있지 않습니다. `scripts/vault_stats.py`로 추적합니다.

<a id="hub-pages"></a>

## 허브 페이지

어떤 페이지에는 링크가 쌓이고 쌓여 결국 모든 것이 그곳을 거쳐 가게 됩니다. 모든 자료가 건드리는 일반적인 개념이 허브가 되고, 허브가 되고 나면 그 주변의 그래프는 더 이상 정보를 주지 못합니다. 모든 것이 모든 것과 두 걸음 거리이기 때문입니다.

해법은 허브를 사람들이 실제로 링크하는 구체적인 아이디어들로 쪼개는 것입니다. 페이지 40개가 폭넓은 개념 하나에 링크한다면, 그 개념의 서로 다른 측면 네 가지에 링크하고 있는 것입니다.

<a id="decorative-links"></a>

## 장식용 링크

링크는 두 페이지가 따라가 볼 만한 방식으로 관련되어 있다는 주장입니다. 단어가 마침 나왔다는 이유로 더한 링크는 노이즈이며, 충분히 많아지면 빈 그래프를 쓸 수 없는 것과 똑같은 방식으로 그래프를 쓸 수 없게 만듭니다.

기준은 이것입니다. 이 주제를 조사하는 중에 이 링크를 따라가겠습니까? 그렇지 않다면 삭제합니다.
