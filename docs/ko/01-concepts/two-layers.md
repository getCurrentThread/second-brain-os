# 두 계층

대부분의 세컨드 브레인 설정은 하나의 형태를 골라 두 가지 일을 시키려다 실패합니다.

**지식 계층**은 "X에 대해 나는 무엇을 아는가"에 답합니다. 아이디어별로 정리되고, 끝없이 커지며, 가치는 페이지 사이의 링크에 있습니다. 이것이 LLM 위키 패턴입니다. 자료가 들어가고, 개념이 나오고, 모든 것이 연결됩니다.

**프로젝트 계층**은 "이번 주에 나는 무엇을 하는가"에 답합니다. 입력에서 출력으로 가는 파이프라인으로 정리되며, 대부분은 프로젝트가 끝나는 순간 식어 버립니다.

둘을 합치면 각기 다른 방식으로 실패합니다. 프로젝트 폴더가 들어간 위키는 죽은 작업 목록으로 가득 차서 모든 검색을 나쁘게 만듭니다. 개념 노트가 들어간 프로젝트 시스템은 작업 파일을, 일하는 동안 아무도 열지 않는 자료 밑에 묻어 버립니다.

<a id="how-they-connect"></a>

## 둘이 연결되는 방식

프로젝트는 지식 계층을 소비하고, 그 결과를 다시 지식 계층에 채웁니다.

```
        wiki/concepts ──────> project Inputs/
              ▲                      │
              │                      ▼
        ingest what                Process/ ──> Outputs/
        you learned                              │
              └──────────────────────────────────┘
```

작업은 보관할 가치가 있는 자료를 만듭니다. 자신이 끝낸 작업을 인제스트하는 것은 거의 모든 사람이 건너뛰는 단계이며, 한 분야의 두 번째 프로젝트를 첫 번째보다 눈에 띄게 빠르게 만드는 것이 바로 이 단계입니다.

<a id="which-to-build-first"></a>

## 무엇을 먼저 만들 것인가

많이 읽는데 남는 것이 적다면 지식 계층입니다.

매일 아침 채팅창에 자신의 상황을 다시 설명하는 것이 문제라면 프로젝트 계층입니다.

결국에는 둘 다 필요합니다. 한 폴더 안에서 둘을 분리해 두는 배치는 [볼트 구조](../02-setup/vault-structure.md)를 보십시오.
