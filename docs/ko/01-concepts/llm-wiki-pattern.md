# LLM 위키 패턴

이 가이드가 구현하는 구체적인 패턴입니다. Andrej Karpathy가 2026년 4월 4일에 gist로 공개했습니다.

한 문장으로 말하는 역전은 이렇습니다. 사람이 노트를 유지하면서 가끔 AI에게 노트에 대해 묻는 대신, AI가 위키를 유지하고 사람은 그것을 읽습니다.

<a id="what-the-pattern-specifies"></a>

## 패턴이 규정하는 것

**위키가 중심입니다.** 원본 자료는 보관해 두고 좀처럼 열지 않는 아카이브입니다. 위키는 사람과 에이전트가 함께 작업의 바탕으로 삼는 것으로, 쉬운 말로 쓰고, 페이지 하나에 아이디어 하나를 담고, 촘촘히 링크합니다.

**요약이 아니라 컴파일입니다.** 새 자료는 또 하나의 요약으로 따로 쌓이지 않고 기존 페이지에 통합됩니다. 개념 페이지는 자료가 쌓일수록 나아지고, 자료마다 무엇을 말했는지 나열하는 목록으로 변하지 않습니다.

**작업은 세 가지입니다.** 인제스트는 새 자료를 들여옵니다. 린트는 구조가 흐트러지지 않게 지킵니다. 질의는 위키에서 답합니다. 나머지는 모두 이 셋의 변형입니다.

<a id="why-it-holds-up"></a>

## 이 패턴이 버티는 이유

이전의 모든 시스템을 죽인 단 하나의 작업을 없애 주기 때문입니다. 논문을 읽을 때마다 노트 쉰 개를 서로 연결하는 일은 정말 지루해서 사람이 결국 그만두고, 유지하는 사람이 지치면 위키는 죽습니다.

다른 이유는 인프라가 필요 없다는 점입니다. 마크다운 파일, 위키링크, 파일을 읽고 쓸 수 있는 에이전트면 됩니다. 데이터베이스도, 최신으로 유지해야 하는 인덱스도, 의존해야 하는 서비스도 없습니다.

<a id="where-the-gist-stops"></a>

## gist가 멈추는 곳

gist는 구현이 아니라 의도를 설명합니다. 새 자료를 통합하고, 주기적으로 린트하고, 위키를 중심에 둔다는 것입니다.

구체적인 동작 방식은 정해져 있지 않고, 그래서 구현마다 다릅니다. 통합이 모순을 어떻게 다루는지, 페이지에 무엇이 들어가야 하는지, 린트를 언제 돌리는지, 위키를 누구를 위해 쓰는지가 그렇습니다. 이 가이드의 답은 [구조화](../04-structuring/README.md)에 있으며, 이는 패턴 자체가 아니라 하나의 의견입니다.

<a id="what-people-build-on-top"></a>

## 사람들이 그 위에 쌓는 것

흔한 확장은 저널 계층, 프로젝트 계층, 예약 자동화입니다. 이 가이드는 둘째와 셋째를 [두 계층](two-layers.md)과 [에이전트](../06-agents/README.md)에서 다룹니다.

이 패턴이 빠르게 퍼진 것은 기본 요소가 평범하기 때문이기도 합니다. 에이전트와 폴더만 있으면 누구나 돌릴 수 있고, 구현체도 모두 읽을 수 있는 마크다운입니다. 읽을 만한 구현체는 [자료](../../../resources/skills.md)를 보십시오.
