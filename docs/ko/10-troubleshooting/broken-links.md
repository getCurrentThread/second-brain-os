# 깨진 링크와 고아 페이지

```bash
python3 scripts/link_check.py ~/brain
```

<a id="why-renames-break-links"></a>

## 이름을 바꾸면 링크가 깨지는 이유

Obsidian은 앱 안에서 이름을 바꾸면 링크를 갱신합니다. 에이전트가 파일 이름을 직접 바꾸면 갱신되지 않으며, 이것이 에이전트가 관리하는 볼트에서 깨진 링크가 생기는 가장 흔한 원인입니다.

`CLAUDE.md`에 규칙을 두어 막으십시오. 이름을 바꾸면 모든 인바운드 링크를 갱신하고, 옛 이름을 별칭으로 추가하고, `log.md`에 기록합니다. [이름 짓기와 별칭](../04-structuring/naming-and-aliases.md)을 보십시오.

<a id="fixing-in-bulk"></a>

## 일괄 수정

두 범주가 있으며, 처리 방식이 다릅니다.

**오타와 이름 변경**은 고칩니다. 링크를 올바른 페이지로 향하게 합니다. 자동화해도 안전합니다.

**진짜 빈틈**, 곧 대상이 처음부터 없었던 경우는 `index.md`의 Gaps에 넣습니다. 그것을 채우려고 빈 페이지를 만들지 마십시오. 빈 페이지는 기록된 빈틈보다 나쁩니다. 다룬 것처럼 보이기 때문입니다.

항상 Git 상태가 깨끗할 때 하십시오. 잘못된 일괄 수정도 명령 하나로 되돌릴 수 있습니다.

<a id="orphans"></a>

## 고아 페이지

아무것도 링크하지 않는 페이지입니다. 세 경우가 있습니다.

**링크되어야 하는데 안 된 경우.** 그 페이지를 참조해야 할 페이지를 찾아 링크를 추가합니다. 일괄 가져오기 뒤에 흔한 경우입니다.

**정말 독립적인 경우.** 드물며, 대개 그 자료가 위키에 속하지 않는다는 신호입니다. 참고 자료와 체크리스트는 프로젝트 폴더에 둡니다.

**실패한 인제스트.** 끝내 연결되지 못한 스텁입니다. `raw/`의 원본에서 다시 인제스트합니다.

<a id="preventing-both-at-ingest"></a>

## 인제스트 단계에서 둘 다 막기

이 작업의 대부분을 없애 주는 규칙은 이것입니다. 같은 실행 안에서 양방향으로 링크하기 전에는 아무것도 인제스트된 것이 아닙니다.

링크되지 않은 페이지로 끝나는 인제스트는 끝나지 않은 인제스트입니다. 매주 뒷정리하는 대신 스킬에서 강제하십시오.

<a id="after-a-big-import"></a>

## 대규모 가져오기 뒤

항상 린트하십시오. 대규모 백필은 어김없이 고아 페이지와 거의 중복된 페이지를 만듭니다. 에이전트가 서로 겹치는 자료를 빠르게 훑고 지나갔기 때문입니다.

여기에도 예산을 잡으십시오. 자료 천 건을 가져온 뒤에는 린트 한 차례와 병합 검토가 따라야 하며, 이 단계를 건너뛰는 것이 볼트를 영구히 어수선하게 만듭니다.
